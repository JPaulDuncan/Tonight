# Tonight

**Tonight** is an open-source battle royale built in **Unity 6** with art authored
procedurally in **Blender**, driven end-to-end by AI agents over **MCP** (Model
Context Protocol).

100 players. One shrinking storm. Harvest, build, fight, survive until morning.

> **Status: Pre-production.** This repository currently contains the complete
> design and technical specification, a runnable Unity project skeleton with the
> Blueprint data layer and core gameplay systems, and a Blender asset-generation
> pipeline. It is not yet a playable game. See [docs/03-roadmap.md](docs/03-roadmap.md)
> for what ships when.

---

## Why this repo looks the way it does

Three decisions shape everything here. Read these before reading code.

### 1. "Blueprints" means data assets, not Unreal

Unreal's Blueprints do not exist in Unity. The project brief asked to *prefer
Blueprints*, so Tonight implements the idea rather than the feature: **content is
authored as data assets in the Editor, not as C# in a text file.**

| Unreal concept | Tonight's equivalent |
| --- | --- |
| Blueprint Class | `ScriptableObject` **Blueprint** asset (`WeaponBlueprint`, `BuildPieceBlueprint`, …) |
| Blueprint Actor | Prefab Variant bound to a Blueprint asset |
| Blueprint Graph | Unity Visual Scripting graph, or a Blueprint-referenced `AbilityGraph` |
| Data Table | `BlueprintRegistry` / `LootTableBlueprint` |

A designer adds a new weapon by right-clicking → *Create → Tonight → Blueprints →
Weapon*, filling in fields, and dropping it into a loot table. **No C# change, no
recompile, no programmer.** If adding content to a system requires editing C#,
that system is considered unfinished. This rule is enforced in review — see
[docs/blueprints/README.md](docs/blueprints/README.md).

### 2. Art is generated by script, not modeled by hand

Every mesh in `blender/scripts/` is produced by a deterministic Python generator
that runs headless in Blender. Re-running a generator reproduces the exact same
mesh, byte-for-byte where Blender allows. This means art is reviewable in a diff,
regenerable in CI, and drivable by an agent over MCP.

### 3. MCP is a first-class build tool

Both the Unity Editor and Blender are driven by MCP servers, so an agent can
create a scene, wire a prefab, generate a mesh, and export it without a human
touching the GUI. See [docs/mcp/README.md](docs/mcp/README.md).

## Quick start

### Read the design first

```
docs/00-vision.md  →  docs/01-game-design-document.md  →  docs/02-technical-architecture.md
```

### Run the Blender pipeline (no Unity needed)

```bash
python3 -m pip install -r tools/requirements.txt
python3 -m pytest blender/tests -q           # library tests, run without Blender
blender --background --python blender/scripts/build_all.py    # needs Blender 4.2+
```

Outputs land in `blender/exports/` and are picked up by Unity's importer.

### Open the Unity project

1. Install **Unity 6000.0 LTS** or newer via Unity Hub.
2. Open `unity/Tonight/`.
3. First import takes several minutes while packages resolve.

### Wire up MCP

See [docs/mcp/README.md](docs/mcp/README.md) for the full setup. The short version:

```bash
# Blender side: install the addon, then enable it in Blender and hit "Connect"
uvx blender-mcp     # launched automatically by .mcp.json

# Unity side: Package Manager → Add from git URL
# https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#v10.0.0
```
